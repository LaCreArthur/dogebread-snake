# Devlog — DogeBread Snake

## 2026-02-15 00:39–01:00 — From scratch to playable battle royale

### What was built
Full snake battle royale game in Rust/Bevy 0.18, coded entirely by AI (Claude) with zero editor:
- 6-snake arena (1 player + 5 AI with 3 personality types)
- 40x40 grid, camera follow, minimap
- Arena shrinking every 12s (battle royale mechanic)
- Speed increase over time
- Score + kills tracking, game over scoreboard
- Death blink animation, spectating mode
- Full game state flow: WaitingToStart → Playing → GameOver

1. Initial 4-snake with AI

4. **Arena shrinking + WaitingToStart** (biggest feature)

6. Kill credit tracking

### Key learnings (see LEARNINGS.md)

- Auto-screenshot via Bevy native API + env var toggle = autonomous visual verification
- ECS query conflicts solved with `Without<T>` filter
- Iteration speed accelerated: early commits had 3-4 compile errors, last 5 were clean first try

### What's NOT obvious
- The project was scaffolded across 2 sessions (first session: Rust install, API research, initial scaffolding; second session: this devlog's 21 min of rapid feature work)

- SimpleRng uses PCG algorithm to avoid external rand dependency
- Grid cells store their GridPos for dynamic recoloring during arena shrink

## 2026-03-01 — Doge Sprites: Replace Placeholder Graphics

### What was built
Replaced all colored-square placeholder graphics with actual pixel-art sprites:
- **Doge head** (32×32 RGBA PNG) — pixel-art Shiba Inu face: oval tan face, pointed ears, two black eyes with white highlights, dark nose, small smile, rosy cheeks
- **Coin sprite** (32×32 RGBA PNG) — gold Dogecoin: circular gradient coin with Ð (D-stroke) symbol, specular highlight top-left

### Architecture decisions

**Embedded sprites, not loaded from disk**
Used `include_bytes!()` to bake both PNGs directly into the binary. This is mandatory for WASM — there's no filesystem, so runtime file loading would require an async asset server (adds complexity). At 402B + 671B, the sprites add < 1 KB to the binary. No production impact.

**Startup resource pattern (`SpriteAssets`)**
Single startup system `load_sprite_assets` decodes both PNGs via `Image::from_buffer(...)` with `ImageSampler::nearest()` (pixel art, no blurring) and inserts them as a `SpriteAssets` resource. Both `render_snakes` and `render_food` take `Res<SpriteAssets>` — clean dependency injection.

**Head vs body rendering split**
- Segment index 0 (head): `Sprite { image: doge_head.clone(), custom_size: Vec2::splat(CELL_SIZE), .. }`. Color tint = `Color::WHITE` for living snakes; gray+blink alpha for dead snakes (death animation preserved).
- Segment index 1+ (body): unchanged `Sprite::from_color` — colored squares keep per-snake color identity readable at a glance.
- Food: `Sprite { image: coin.clone(), custom_size: pulsed_size, .. }` — coin still pulses via the existing sine-wave animation.

**Removed `COLOR_FOOD`** constant (was dead code once food switched to coin sprite).

**Sprite generation**
Sprites generated by `generate_sprites.py` (Python/PIL, kept in repo). Means sprites can be iterated without touching Rust — just re-run the script and rebuild. The generation script is deterministic so re-generating produces bit-identical output.
